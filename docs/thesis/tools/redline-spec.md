# Redline tool spec: apply draft edit lists to the manuscript as tracked changes

## Purpose

Apply the edit lists in `docs/thesis/drafts/*.md` (format defined in `docs/thesis/drafts/README.md`) to the Drive copy of the thesis, `docs/thesis/manuscript/BAB1-5-REVISI-TELAAH-drive-original.docx`, producing a `.docx` whose every change is a Word tracked change (insertions `<w:ins>`, deletions `<w:del>`), authored "Syahid Nurrohim", so the author and examiner can review and accept them in Word or Google Docs. Untouched paragraphs, including their Zotero citation hyperlinks (24 unique zotero.org/google-docs links in `word/_rels/document.xml.rels`), must stay byte-identical.

## Behaviour

1. Parse edit blocks: `### E-<id> (closes: ...)`, `Operation:`, `Anchor:`, optional `Occurrence:`, optional `Style:`, optional `Numbering:`, `Text:` (multi-line until `Rationale:`), `Rationale:`. Report malformed blocks with their id and line number; never guess.
2. Paragraph matching: plain text of a `w:p` = concatenation of its `w:t` text including runs inside `w:hyperlink`, excluding `w:delText`, whitespace collapsed. An anchor matches a paragraph when the anchor equals the paragraph text, or the paragraph text starts with the anchor and the anchor is at least 40 characters. Search the body including table cells. Zero matches or more than one (without `Occurrence`) is an error that names the edit id and the candidate paragraphs. Matching runs against the original document, not against paragraphs inserted by earlier edits, unless an anchor only exists in inserted text (then match inserted paragraphs and say so in the report).
3. Operations (all tracked, one `w:id` counter for the whole document, `w:date` = run date in ISO 8601 UTC):
   - `replace`: every existing run of the paragraph (including runs inside hyperlinks) is wrapped in `w:del` with `w:t` turned into `w:delText`; the first line of `Text` is added as `w:ins` runs in the same paragraph, copying the first original run's `w:rPr`; further lines become new paragraphs inserted after it, copying the paragraph's `w:pPr` after any change below.
   - `Style:` on `replace`: when the resolved style id differs from the paragraph's style (its `w:pStyle`, else the default paragraph style), `w:pStyle` is set to it. A style that is not a list alias (`list_item` false in `style_aliases.json`) also removes `w:numPr` unless the edit has a `Numbering:` key. The previous `w:pPr` goes into a `w:pPrChange` (author and date of the run). When neither the style nor the numbering changes, nothing is written. A paragraph inserted earlier in the run changes directly, without `w:pPrChange`; a paragraph that already holds a `w:pPrChange` cannot record a second one, so the edit is a conflict error. A style neither defined nor aliased is a warning and changes nothing. The report's Notes column marks each replace whose paragraph properties changed: `pPr changed (style <old> to <new>; numId <old> to <new>)`.
   - `insert_after` / `insert_before`: new `w:p` elements; paragraph properties copied from the anchor paragraph unless `Style:` names a style, in which case the style id is looked up by its display name in `word/styles.xml` (built-in and custom names; error if absent); the new paragraph mark is tracked (`w:pPr/w:rPr/w:ins`) and all runs are inside `w:ins`.
   - `Numbering:` (optional on `replace`, `insert_after` and `insert_before` with a paragraph anchor; a parse error on any other operation, on `ROW:` and `TABLE:` anchors, and for any other value) places the edit's paragraphs in a list. `continue <prefix>` copies the `w:numPr` (numId and ilvl) of the paragraph whose plain text the prefix selects. `new <prefix>` appends one `w:num` to `word/numbering.xml` that points at the same `w:abstractNumId` as that paragraph's list, with `w:lvlOverride/w:startOverride` 1 for its level and a copy of the old `w:num`'s overrides of other levels, and gives every paragraph of the edit the new numId at that level. `none` removes `w:numPr`. The prefix is matched with the anchor rules (whole text, or a prefix of at least 40 characters), first among the original paragraphs and then among paragraphs inserted earlier in the run; it must select exactly one paragraph, and that paragraph must carry a `w:numPr` (for `new`, also a `w:num` in `word/numbering.xml`), or the edit is an error. `check` lists an unmatched or ambiguous prefix with the anchor failures. Inserted paragraphs take the `w:numPr` directly; on `replace` the change is tracked as above and further Text lines carry the same `w:numPr`. The new `w:num` in `word/numbering.xml` is not tracked (as with `restart-lists`); that part is the only one besides `word/document.xml` that apply rewrites, and only when an edit uses `new`.
   - `delete`: all runs wrapped in `w:del`, paragraph mark deleted (`w:pPr/w:rPr/w:del`, placed first in rPr per schema order).
   - Inline formatting in `Text`: `*text*` becomes an italic run, `**text**` bold. Everything else is literal, including `[REF:key]`, `[n]` and `{{DATA:name}}` tokens.
   - Markdown tables in `Text` (`| a | b |` rows with a `|---|` separator) become a `w:tbl` inserted as a tracked table: table properties copied from the first existing table in the document (borders), each row with `w:trPr/w:ins`, each cell paragraph's mark and runs tracked; header row bold.
4. Token fill pass (separate command): replace `{{DATA:name}}` occurrences inside tracked insertions with values from a JSON file; report tokens without values and values without tokens.
5. Output: the revised `.docx` and a Markdown report: per edit id, status (applied / error), matched paragraph excerpt, operation; a summary count; the validate.py result.

## CLI

`python -m redline apply --docx IN --edits drafts/A-front-bab1.md [--edits ...] --author "Syahid Nurrohim" --out OUT --report REPORT.md`
`python -m redline fill --docx IN --values values.json --out OUT --report REPORT.md`
`python -m redline check --edits drafts/*.md --docx IN` (dry run: parse and match only, no writing)

## Acceptance

- Unit tests cover: parser (good and malformed blocks), matcher (exact, prefix, duplicate, zero match, inside table, inside hyperlink), each operation's XML (ins/del structure, delText, rPr copied, paragraph-mark tracking order), italic/bold runs, table insertion, style lookup, token fill.
- End-to-end test: apply `drafts/A-front-bab1.md` to a copy of the real manuscript; validate.py with `--author` reports no untracked changes; all hyperlinks in paragraphs not touched by any edit are unchanged (compare their XML before and after); the number of `w:ins`/`w:del` elements matches the report.
- `check` mode run over drafts A, B, C, E reports every anchor as matched exactly once (or names the failures for the drafter to fix).
- No em-dash characters in code, comments, or reports. A concise docstring on every function. Readable over clever.

## Pipeline order

Run the passes in this order, each on the output of the one before:

1. `registry` (drafts to `references.json`)
2. `prep` (harness results to the fill folder and `landscape-captions.txt`; reads no `.docx`)
3. `apply` (edits as tracked changes)
4. `landscape` (wide result tables on a landscape page of their own, for the captions `prep` listed)
5. `fill` (TABLE, FIGURE and DATA tokens, from the folder `prep` wrote)
6. `cite` (renumber citations, rebuild the reference list)
7. `italics` (first-use italics for foreign terms)
8. `headers` (repeat the first row of tables)
9. `restart-lists` (numbered lists restart at 1)
10. `breaks` (page break before a next-page section break)

`prep --layout docs/thesis/fill-layout.json --root REPO --out FOLDER --report REPORT [--results FOLDER] [--drafts DRAFT ...]` turns the harness output (the layout's `results_dir`, or `--results` for a trial on scratch output) into the folder `fill` reads, following the layout decisions in `docs/thesis/fill-layout.json`. It writes one flat `values.json` (the harness `values` and `extras` plus the layout's `recorded_values`; a name given twice is a problem, and the file is checked with `fill`'s own reader), one `<token>.md` per layout table (the exact `columns`, or every column except `drop`, columns empty or `-` on every row and a `Sesi` column with one value; `transpose` turns rows into columns), and one `<token>.png` per figure (a path below `--root`, or the results file that a value names). A `manual` table writes nothing and is listed with its note. Each written table goes portrait when it fits the portrait text width at the 10 pt floor with 60-twip cell margins (the last size `fill` tries), else landscape; a table that fits neither is a problem that sends the layout back. The landscape captions go to `landscape-captions.txt`, and the report prints the `landscape` command for them. With `--drafts` the report lists every `{{DATA:name}}` of the drafts that has no value, used in edit text or only in the notes sections, with the harness's uncomputed reason; it always lists every uncomputed value. `--out` must not exist yet or be empty, and any problem makes the run fail.

`landscape --at PREFIX [PREFIX ...]` runs after `apply`, whose edits write the captions and `{{TABLE:name}}` paragraphs it looks for, and before `fill`, which sizes each table for the text column of the section that holds its token. With the BAB IV section's page (`pgSz` 11909 by 16834) and side margins (2267 left, 1700 right) that column is 7942 twips in portrait and 12867 twips in landscape. Each prefix names a caption: the one paragraph directly in the body whose accepted text starts with it. The caption and the run of body elements right after it that are tables (a fully deleted one too), `{{TABLE:name}}` paragraphs or table notes (paragraphs whose accepted text starts with `Catatan:`, which stay on the page of their table) form the block; the run stops at the first element of any other kind and must hold at least one table or token. An inserted empty paragraph before the caption ends the portrait part with a copy of the holding section's `w:sectPr`; one inserted after the block ends the landscape section with the same copy turned landscape (width and height swapped, `w:orient="landscape"`, margins unchanged, as in the manuscript's own landscape sections). Both copies drop `w:sectPrChange` and keep their header and footer references, and both paragraph marks are tracked insertions, so rejecting them gives back the single portrait section; the holding section's own `w:sectPr` is untouched, so the text after the table goes on in portrait on a new page. The report names each prefix's caption, block, text width before and after, and outcome. A prefix that matches no caption or several, a caption whose run holds no table or token, a section break inside the block, or a holding section that is not portrait, restarts its page numbers (`w:pgNumType w:start`) or has a different first page (`w:titlePg`) is listed under Problems and skipped. `breaks` still removes a page-break-only paragraph that ends up right before one of the new next-page section breaks, and `headers` marks a table inside a landscape section like any other.

`italics` runs after the final `fill`. It treats every `{{...}}` span as a separator and never splits or restyles one, so an unfilled token survives it, but running it after the last fill keeps the first-use count based on the real text (a value filled later could contain a listed term). `headers`, `restart-lists` and `breaks` only change properties and may follow in any order after `italics`.
